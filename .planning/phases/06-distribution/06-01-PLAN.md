**SYNC-03 requirement: CloudKit schema must be promoted to Production BEFORE archiving or uploading to TestFlight.**

TestFlight and App Store builds connect to the Production CloudKit environment. If the schema is not promoted, iCloud sync silently fails — data saves locally but never syncs to iCloud. This is the #1 CloudKit gotcha for new app launches.

**WARNING: Schema promotion is irreversible.** Once promoted, fields can only be added to Production — they cannot be renamed or removed. All fields in SchemaV1 (Goal, CompletionEvent) and SchemaV2 (UserProfile including isPublic field) are finalized; promotion is safe.

### Pre-promotion: Verify Development schema is complete

The CloudKit Development environment auto-creates record types the first time the app writes to them. Before promoting, confirm all record types are present:

1. Run a DEBUG build on a physical device (not Simulator — CloudKit is skipped on Simulator per `ModelContainerFactory.swift`)
2. Perform one action for each model: create a Goal, complete it (creates CompletionEvent), open Profile tab (creates UserProfile)
3. If any record type is still missing, `ModelContainerFactory.initializeCloudKitSchema()` can be called in DEBUG mode to force registration

Alternatively, skip to step 4 and check in the console — if all record types are already present from prior development testing, proceed directly.

### Promotion steps

1. Open **https://cloudkit.developer.apple.com** in a browser
2. Select **CloudKit Database** from the tools list
3. In the container dropdown (top-left), select **iCloud.com.kyleharrington.VitaminG**
   (Container ID confirmed in `VitaminG/VitaminG/VitaminG/VitaminG.entitlements`)
4. Ensure the environment toggle shows **Development** (not Production)
5. In the left sidebar, navigate to **Schema → Deploy Schema Changes...**
6. Review the diff — confirm it includes all of the following record types:
   - `CD_Goal` — fields: `CD_id`, `CD_title`, `CD_goalDescription`, `CD_tierRawValue`, `CD_isCompleted`, `CD_creationDate`, `CD_associatedInspiration`, `CD_isPublic`
   - `CD_CompletionEvent` — fields: `CD_id`, `CD_completedAt`, `CD_tierRawValue`
   - `CD_UserProfile` — fields: `CD_id`, `CD_displayName`, `CD_avatarColorHex`, `CD_isPublic`, `CD_cloudKitPublicRecordID`, `CD_photoData`
   - Note: SwiftData prefixes all CloudKit record type names with `CD_`
7. If `CD_isPublic` is absent from `CD_Goal` or any SchemaV2 field is missing from `CD_UserProfile` — stop. Run the DEBUG build to trigger registration, then return here.
8. Click **Deploy** to promote the schema to Production

### Post-promotion verification

After deployment:
1. Switch the CloudKit Console environment toggle to **Production**
2. Navigate to Schema → Record Types
3. Confirm `CD_Goal`, `CD_CompletionEvent`, and `CD_UserProfile` are all present
4. If they are present — schema promotion is complete. Continue to Task 5 (archive).
