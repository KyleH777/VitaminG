## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Notification userInfo "userChallengeID" → .onOpenURL URL path → DeepLinkParser → AppRouter.pendingChallengeCheckInID | Full untrusted path from notification delivery through URL dispatch; UUID must be validated at two points |
| ChallengeCheckInDeepLinkItem.id (String) → UUID(uuidString:) → SwiftData fetch | UUID format validated before SwiftData query; malformed IDs produce nil match, sheet shows nothing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-24 | Tampering | Malformed UUID string in notification deep link → ContentView SwiftData fetch | mitigate | `UUID(uuidString: item.id)` returns nil for non-UUID strings; `allUserChallenges.first(where: { $0.id == uuid })` returns nil for unknown UUIDs; sheet body renders nothing — no crash, no data exposure. |
| T-13-25 | Tampering | Valid UUID for a different user's challenge (impossible on-device; defense-in-depth) | accept | SwiftData stores only the current device user's data (iCloud private DB). No cross-user data accessible on device. |
| T-13-26 | Spoofing | Third-party app registering vitaming:// scheme | accept | iOS URL scheme dispatch is first-registered-wins; iOS 14+ uses Universal Links for collision-resistant deep links. vitaming:// is sufficient for local notification routing. Out-of-scope for Phase 13. |
</threat_model>
