**Create `ProfileSharingService.swift`** in the Services directory:

```swift
import CloudKit

/// Manages CloudKit public database writes for profile sharing.
/// Only displayName and avatarColorHex are shared publicly — never photoData or personal data.
enum ProfileSharingService {

    private static let containerID = "iCloud.com.kyleharrington.VitaminG"
    private static let recordType = "PublicProfile"

    /// Saves a PublicProfile record to CloudKit public database.
    /// Returns the recordID.recordName string for storage in UserProfile.cloudKitPublicRecordID.
    /// If cloudKitPublicRecordID already exists, updates the existing record instead of creating a new one.
    static func publishProfile(
        displayName: String?,
        avatarColorHex: String?,
        existingRecordID: String?
    ) async throws -> String {
        let container = CKContainer(identifier: containerID)
        let publicDB = container.publicCloudDatabase

        let record: CKRecord
        if let existingID = existingRecordID {
            // Update existing record
            let recordID = CKRecord.ID(recordName: existingID)
            record = try await publicDB.record(for: recordID)
        } else {
            // Create new record
            record = CKRecord(recordType: recordType)
        }

        record["displayName"] = (displayName ?? "") as CKRecordValue
        record["avatarColorHex"] = (avatarColorHex ?? "") as CKRecordValue

        let savedRecord = try await publicDB.save(record)
        return savedRecord.recordID.recordName
    }

    /// Deletes the PublicProfile record from CloudKit public database.
    /// Silently succeeds if record does not exist (already deleted).
    static func unpublishProfile(recordID: String) async throws {
        let container = CKContainer(identifier: containerID)
        let publicDB = container.publicCloudDatabase
        let ckRecordID = CKRecord.ID(recordName: recordID)

        do {
            try await publicDB.deleteRecord(withID: ckRecordID)
        } catch let error as CKError where error.code == .unknownItem {
            // Record already deleted — not an error
        }
    }
}
```

CRITICAL per D-05 and threat model: The PublicProfile record contains ONLY displayName and avatarColorHex. Never include photoData, goal details, or any other personal data. Goal visibility is handled separately (future phase for public profile viewing).

1. **Update `toggleProfilePublic(context:)`** to trigger CloudKit writes:

```swift
func toggleProfilePublic(context: ModelContext) {
    guard let profile else { return }
    let newValue = !profile.isPublic
    profile.isPublic = newValue
    try? context.save()

    if newValue {
        // Going public — write to CloudKit
        Task { @MainActor in
            do {
                let recordID = try await ProfileSharingService.publishProfile(
                    displayName: profile.displayName,
                    avatarColorHex: profile.avatarColorHex,
                    existingRecordID: profile.cloudKitPublicRecordID
                )
                profile.cloudKitPublicRecordID = recordID
                try? context.save()
            } catch {
                // CloudKit write failed — show alert but keep toggle ON (optimistic UI per UI-SPEC)
                cloudKitError = error.localizedDescription
                showingCloudKitError = true
            }
        }
    } else {
        // Going private — delete CloudKit public record if exists
        if let recordID = profile.cloudKitPublicRecordID {
            Task {
                try? await ProfileSharingService.unpublishProfile(recordID: recordID)
            }
            // Clear the recordID so share link disappears
            profile.cloudKitPublicRecordID = nil
            try? context.save()
        }
    }
}
```

Note on going private: Per CONTEXT.md D-06, when Private the Share Profile button is disabled. We DO delete the public record (contrary to RESEARCH.md's conservative "ASSUMED" note) because leaving orphaned public records is a privacy concern — the user explicitly chose to go private. The `unpublishProfile` call handles already-deleted records gracefully.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App -> CloudKit public DB | Profile data crosses from local device to publicly accessible CloudKit database |
| CloudKit public DB -> Any reader | Anyone with the recordID can read the PublicProfile record |
| Deep link URL -> External apps | URL is shared via system share sheet to arbitrary apps |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-08 | Information Disclosure | ProfileSharingService.publishProfile | mitigate | Only displayName and avatarColorHex written to public record — never photoData, goal descriptions, inspiration text, or completion data. Explicit field allowlist in publishProfile method. |
| T-07-09 | Tampering | CKRecord fields | mitigate | Only the profile owner can write to their PublicProfile record (CloudKit creator-based ACL). No other user can modify it. |
| T-07-10 | Repudiation | unpublishProfile | accept | User can toggle private and public record is deleted. No audit trail — acceptable for a personal gratitude app with no compliance requirements. |
| T-07-11 | Denial of Service | CloudKit write failure | mitigate | On publish failure: show alert per UI-SPEC, keep toggle ON (optimistic UI, CloudKit will retry on connectivity restore). On unpublish failure: silently ignore (record becomes orphaned but inaccessible since share link is removed). |
| T-07-12 | Information Disclosure | Deep link URL | accept | recordID in URL is a UUID-like CloudKit identifier — not guessable, not sequential. Acceptable risk for share-link-only distribution model. |
</threat_model>
