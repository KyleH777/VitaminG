<objective>
Build the iOS-side AI plumbing: `AIProxyService` (singleton, @Observable, protocol-backed) and `AIViewModel` (@MainActor @Observable). AIProxyService performs URLSession POSTs to the Cloudflare Worker deployed in Plan 01, caches successful Claude responses under date-string UserDefaults keys per D-03/D-06, and silently falls back to `VGQuoteBank.todaysQuote()` or 3 static suggestions on any network error. AIViewModel owns AI state for Views, exposes `motivationLabel` ("YOUR DOSE"/"TODAY'S DOSE") per D-01, and constructs the goal-data payload from `WidgetDataProvider.build()` (single source of truth, per RESEARCH.md Architecture Map). This plan turns the Wave 0 RED test files GREEN.

Purpose: Decouple network/caching/fallback (AIProxyService) from view-state (AIViewModel) so Plans 03–04 wire UI without re-implementing logic. Protocol-backed service enables unit tests without the deployed Worker (per VALIDATION.md test protocol).
Output: AIProxyService.swift + AIViewModel.swift, both files added to the VitaminG Xcode target and both test files GREEN.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| iOS app → Cloudflare Worker | URLSession POST over HTTPS with JSON body containing user goal titles, streak count, and shared-secret token |
| UserDefaults | Local on-device cache; not a security boundary in this codebase (treated as untrusted per CLAUDE.md but no PII leaves device beyond what's sent to Worker) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-01 | Information Disclosure | Anthropic API key in iOS binary | mitigate | AIProxyService.swift does NOT reference any `sk-ant-` prefix or Anthropic API endpoint directly — only `workerURL`. Anthropic key remains in Cloudflare env (set in Plan 01). Verification: `strings <built-app>` returns 0 matches for `sk-ant-` and 0 matches for `api.anthropic.com` (the Worker URL is the only network destination). |
| T-28-02 | Spoofing | Worker auth | mitigate | `workerToken` matches the SHARED_TOKEN UUID set in Plan 01. Mismatch causes 401 → silent fallback. T-28-02 is mitigated cooperatively: this plan asserts the token value comes from `28-01-SUMMARY.md`. |
| T-28-04 | Tampering | UserDefaults cache key collision | mitigate | All AI keys are namespaced with `vg_motivation_` and `vg_suggestions_` prefixes per D-03/D-06. Unit tests `test_motivationKey_matchesYYYYMMDDFormat` and `test_suggestionsKey_matchesYYYYMMDDFormat` assert the format and prevent regression. |
| T-28-05 | Tampering | Suggestions Codable round-trip | mitigate | `fetchSuggestions` writes via `JSONEncoder().encode([String]) -> Data` and reads via `JSONDecoder().decode([String].self, from: Data)`. The Pitfall 1 NSArray hazard is avoided by never calling `set([String], forKey:)`. Unit test `test_fetchSuggestions_cacheHit_returnsCachedArray` asserts round-trip. |
| T-28-08 | Denial of Service | Worker timeout / network hang | mitigate | `URLRequest.timeoutInterval = 10` caps wait time. On any throw, fallback path returns valid Swift values; UI never blocks (`isLoading*` toggled in `try`/`catch` blocks). |
| T-28-09 | Information Disclosure | Goal titles sent to Cloudflare logs | accept | Goal titles are user content the app already syncs to CloudKit; Worker logs are scoped to the developer's Cloudflare account. Documented acceptance in RESEARCH.md Security Domain. |
</threat_model>
