<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Apple Sign-In → app | ASAuthorizationAppleIDCredential comes from Apple's secure enclave — trust it for the UID; do not trust fullName on repeat auths (nil by design) |
| WelcomeScreen routing → NavigationStack | Path append must be gated on credential success only; .failure must not advance the path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01-01 | Spoofing | WelcomeScreen Apple Sign-In onCompletion | mitigate | Only advance path (termsAndConditions or login) inside .success case; .failure does nothing — no path mutation |
| T-17-01-02 | Tampering | @AppStorage("vg_appleUserID") written at sign-in | accept | Standard UserDefaults — value sourced from Apple's ASAuthorizationAppleIDCredential.user which is the canonical Apple-issued opaque ID; no user-editable surface |
| T-17-01-03 | Elevation of Privilege | Routing returning vs new user | mitigate | Branch condition checks savedName (stored at name-entry step, not at sign-in); clean install = empty savedName = new user flow, preventing returning-user shortcut for fresh installs |
| T-17-01-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan — first-party Apple frameworks only |
</threat_model>
