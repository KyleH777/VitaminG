    - Import Foundation only (no UIKit needed)
    - enum BlockListService (namespace-only, no instances)
    - private static let key = "vg_blockedUserIDs"

    Five static functions:

    1. blockedUserIDs() -> Set&lt;String&gt;:
       guard let data = UserDefaults.standard.data(forKey: key), let array = try? JSONDecoder().decode([String].self, from: data) else { return [] }; return Set(array)

    2. blockUser(appleUserID: String):
       var ids = blockedUserIDs(); ids.insert(appleUserID)
       if let data = try? JSONEncoder().encode(Array(ids)) { UserDefaults.standard.set(data, forKey: key) }

    3. unblockUser(appleUserID: String):
       var ids = blockedUserIDs(); ids.remove(appleUserID)
       if let data = try? JSONEncoder().encode(Array(ids)) { UserDefaults.standard.set(data, forKey: key) }

    4. isBlocked(appleUserID: String) -> Bool:
       blockedUserIDs().contains(appleUserID)

    5. allBlocked() -> [String]:
       Array(blockedUserIDs()).sorted()

    Create XCTest unit tests at VitaminGTests/BlockListServiceTests.swift.
    BlockListService operates on UserDefaults.standard — use a dedicated test suite key or suiteName to avoid polluting the production UserDefaults. In the setUp() method, call UserDefaults.standard.removeObject(forKey: "vg_blockedUserIDs") to start each test clean.

    Required test cases:

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User email → MFMailComposeViewController | User provides report description; MFMailCompose handles this safely as it sends through Mail.app, not app network layer |
| recordID → BlockListService | recordID from CloudKit (Apple-signed) used as block identifier; not user-editable |
| vg_blockedUserIDs → UserDefaults | Local UserDefaults store; data does not leave device in Phase 17; no sync |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-05-01 | Spoofing | BlockListService uses recordID as block identifier | mitigate | recordID is the CloudKit record name (Apple-assigned, opaque, non-guessable for non-public records); used consistently as the identity anchor across UsernameLookupService and BlockListService |
| T-17-05-02 | Information Disclosure | Report email body includes reporter's Apple User ID | accept | Reporter's Apple User ID is sent to support@vitamingapp.com only — not stored in any public record; this is required for abuse investigation and follows App Store Guideline 1.2 |
| T-17-05-03 | Tampering | Block list in UserDefaults is writable by the app | accept | Block list is read at community feed filter time (Phase 21); local UserDefaults is not publicly accessible; no security boundary crossed |
| T-17-05-04 | Denial of Service | MFMailComposeViewController.canSendMail() returns false on simulator | mitigate | mailto: URL fallback implemented; executor tests mailto: branch on simulator, MFMailCompose branch on device |
| T-17-05-05 | Elevation of Privilege | User blocks themselves via PublicProfileView | accept | PublicProfileView is only presented via deep link with another user's recordID; self-blocking would require the user to navigate to their own public profile link, which stores to UserDefaults locally only and has no app-level consequence |
| T-17-05-SC | Tampering | npm/pip/cargo installs | accept | No package installs — MessageUI is first-party Apple framework |
</threat_model>
