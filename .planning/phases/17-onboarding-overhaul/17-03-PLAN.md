<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UsernameScreen text field → CloudKit | User-typed username crosses trust boundary; must be validated (char set) before query to prevent injection into NSPredicate |
| CloudKit public DB → Username claim | First-write-wins model; post-save verification required for conflict detection |
| appleUserID → CloudKit record name | Apple-issued opaque UID used as record name; not user-editable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-03-01 | Spoofing | Username claim using another user's appleUserID | mitigate | Record name == appleUserID (Apple-signed, not user-controlled); users cannot fabricate a different appleUserID at auth time |
| T-17-03-02 | Tampering | NSPredicate injection via username field | mitigate | Client-side charset validation (letters/digits/underscore only) before query; NSPredicate with %@ binding (parameterized) — not string concatenation |
| T-17-03-03 | Information Disclosure | Username availability leaks existing usernames | accept | By design — availability check is required feature; lowercase normalization prevents case-variant enumeration; no additional PII exposed |
| T-17-03-04 | Elevation of Privilege | Race condition allows two users to claim same username | mitigate | Post-save countRecords re-query (D-17); if count > 1, delete this device's record and force retry; no data corruption |
| T-17-03-05 | Denial of Service | Rapid typing hammers CloudKit with check requests | mitigate | 500ms debounce with Task cancellation; only one in-flight check at a time |
| T-17-03-SC | Tampering | npm/pip/cargo installs | accept | No new package installs — CloudKit is first-party |
</threat_model>
