## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Goal data <-> notification content | Goal titles flow into the notification body; titles are user-entered strings |
| Notification payload <-> lock screen | The body text is rendered by the OS on the lock screen — must contain no sensitive data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-05-01 | Information disclosure | PII in the notification payload | mitigate | The body contains only a hardcoded inspirational message plus one goal title the user themselves wrote — no email, no username, no account identifier; the existing Goal title length/character validation (project-wide String limits) still applies upstream |
| T-19-05-02 | Tampering | Hardcoded message array | accept | `inspirationalMessages` is a compile-time constant — no user input path, no injection surface |
| T-19-05-03 | DoS | Index out of range on rotation | mitigate | The index uses `% inspirationalMessages.count` and `ordinality(...) ?? 1`, so it is always a valid array index even if `ordinality` returns nil |
| T-19-05-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager installs — native UserNotifications/Foundation only; no slopcheck applicable |
</threat_model>
