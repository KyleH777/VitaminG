## Spacing Scale

Declared values (multiples of 4 — iOS point units, not CSS pixels):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon gaps, chip border padding |
| sm | 8pt | Intra-element spacing (VStack row gaps, label-to-value gaps) |
| md | 16pt | Default element spacing, Form section internal padding |
| lg | 24pt | Section padding, horizontal content insets on non-Form screens |
| xl | 32pt | Large section breaks, bottom safe-area padding |
| 2xl | 48pt | Major layout breaks (hero spacer, CTA bottom padding) |
| 3xl | 64pt | Page-level spacer above primary content |

Exceptions:
- **Horizontal insets on AboutView / TipJarView / NudgeTimePickerScreen:** 24pt (`padding(.horizontal, 24)`) — matches established non-Form screen pattern in codebase (NotificationOnboardingScreen uses 28pt; ClayMid screens use 24–28pt)
- **Floating sticky footer bottom clearance:** 12pt below the CTA button within `.safeAreaInset`, with 100pt `.padding(.bottom, 100)` on the ScrollView content so the last bio paragraph is never occluded (RESEARCH.md Pattern 4)
- **Minimum touch target height:** 44pt on all tappable rows and buttons (iOS HIG; enforced via `minHeight: 44` on Button frames)
- **Chip horizontal padding:** 16pt / vertical 10pt (RESEARCH.md time chip pattern)
- **Card corner radius:** 12pt for IAP tier cards; 14pt for primary CTA buttons; 18pt for notification preview card in onboarding

Source: codebase patterns verified in SettingsView.swift, NotificationOnboardingScreen.swift, MilestoneCelebrationView.swift; RESEARCH.md Patterns 4, 6.

## Color

All color tokens reference the adaptive semantic tokens in VGTheme.swift (light/dark variants already defined).

| Role | Token | Light Value | Dark Value | Usage |
|------|-------|-------------|------------|-------|

**Accent (VGTheme.accentTerra) reserved exclusively for:**

2. Selected time chip background on NudgeTimePickerScreen
3. Post-purchase ThankYouView "Done" dismiss button background
4. TipJarView individual "Buy" button per tier (one accent button per tier row)

**Secondary accent (VGTheme.accentSage, `#7A9E7E` / `#95D69C`):**
Reserved for positive confirmation states — the "Enabled" status label in the existing SettingsView notification authorization row. Not introduced in new surfaces.

**Hero / dark backgrounds:**
- ThankYouView full-screen cover: `Color.black.opacity(0.92)` — matches MilestoneCelebrationView exactly (RESEARCH.md Pattern 7)
- NudgeTimePickerScreen: `VGTheme.sandLight` background (light onboarding screens follow this — CameraPermissionScreen pattern)

**Text colors:**
- Primary text: `VGTheme.textPrimary` (clay `#3D2F1E` light / sand `#F2E8D9` dark)
- Secondary text: `VGTheme.textSecondary` (clay 75% alpha light / sand 62% alpha dark)
- Muted / disabled text: `VGTheme.textMuted` / `VGTheme.muted`

## Screen-by-Screen Interaction Contract

### 1. AboutView

**Entry point:** "About Vitamin G" row in SettingsView → Support section → NavigationLink push.

**Layout:**
- `NavigationView` push screen; inherits `.navigationTitle("About Vitamin G")` or inline title via `VGTheme.serif(34)` heading at top of content
- `ScrollView` wraps all content
- Content order: App icon/logo area (optional — Claude's discretion), app name (`VGTheme.serif(34)`), version string (`Label` role, 15pt), horizontal `VGTheme.separator` divider, founder bio text (`Body` role, 17pt, `VGTheme.textPrimary`)
- `.safeAreaInset(edge: .bottom)` renders the floating sticky footer — always visible regardless of scroll position

**Floating sticky footer:**
- Background: `VGTheme.sandLight` (matches page background — creates a blended "dock" effect)
- Button: full-width, 18pt vertical padding, `VGTheme.accentTerra` fill, `VGTheme.warmWhite` text, cornerRadius 14pt
- Label: "Tip the Developer ☕"
- Destination: `NavigationLink(destination: TipJarView())` — push, not sheet
- The footer does NOT overlap content — ScrollView has `.padding(.bottom, 100)` on its content to leave space

**Scroll behavior:** Standard vertical scroll; footer is always accessible without reaching the bottom of content.

**Accessibility:** Bio text supports Dynamic Type. Version string has `.accessibilityLabel("App version \(version)")`.

**States:** Single state — read-only display. No loading, empty, or error states.

---

### 2. TipJarView

**Entry point:** NavigationLink push from AboutView floating footer.

**Layout:**
- NavigationLink push screen; `.navigationTitle("Support the Developer")` or inline `VGTheme.serif(28, weight: .semibold)` heading
- `ScrollView` with 24pt horizontal padding
- Three tier cards in a `VStack(spacing: 16)`:
  - Each card: `VGTheme.surface` background, `RoundedRectangle(cornerRadius: 12)`, 16pt inner padding
  - Card content: emoji (48pt font), tier name (body 17pt semibold), description (caption 13pt muted), price (`product.displayPrice`, body 17pt semibold accentTerra), "Buy" button (accentTerra, capsule shape, 36pt height)
  - Tier order (ascending price): Small Coffee ☕ / Large Coffee ☕☕ / Supporter 💛
- Loading state: `ProgressView()` centered while `TipStore.isLoading == true`
- Error state: `Text("Couldn't load tips. Try again.")` centered with `.foregroundStyle(VGTheme.textMuted)`

**Purchase interaction:**
- User taps "Buy" button on a tier card
- Button shows `.disabled(true)` while purchase is in-flight (prevent double-tap)
- On `.success(.verified)`: `showThankYou = true` triggers `.fullScreenCover(isPresented:)` presenting `ThankYouView`
- On `.userCancelled`: no UI change (purchase sheet dismissed, nothing shown)
- On `.pending` or error: show inline error below the tapped card: "Purchase pending" or `store.purchaseError` in caption 13pt red

**Consumable UX:**
- No "already purchased" state — consumables are always shown as purchasable (D-07)
- All three "Buy" buttons are enabled simultaneously; user can purchase any tier in any order

**States:** loading / loaded / purchasing (individual button disabled) / error / post-purchase (fullScreenCover)

### 3. ThankYouView

**Entry point:** `.fullScreenCover(isPresented: $showThankYou)` from TipJarView after verified purchase.

**Layout (mirrors MilestoneCelebrationView exactly):**
- Background: `Color.black.opacity(0.92).ignoresSafeArea()`
- Confetti: `TimelineView(.animation)` Canvas falling rectangles (60 particles, golden angle scatter) — `.accessibilityHidden(true)`
- Content `VStack(spacing: 24)` centered:
  - ☕ emoji: `.font(.system(size: 64))`, spring entrance animation (scale 0.3→1.0, opacity 0→1)
  - "Thank you!\nYou're the best." — `.font(.title2.bold().fontDesign(.rounded))`, `.foregroundStyle(.white)`, `.multilineTextAlignment(.center)`, 32pt horizontal padding
  - `Spacer()`
  - "Done" button: `.font(.body.weight(.semibold).fontDesign(.rounded))`, `maxWidth: .infinity, minHeight: 44`, `VGTheme.accentTerra` fill, white text, cornerRadius 12pt, 24pt horizontal / 48pt bottom padding

**Entrance animation:** `.spring(response: 0.5, dampingFraction: 0.7)` for emoji scale + opacity. Reduced motion: skip animation, show at full scale/opacity immediately (check `@Environment(\.accessibilityReduceMotion)`).

**Dismiss:** "Done" button calls `onDismiss()` which sets `showThankYou = false`. No auto-dismiss. No swipe-to-dismiss (`.interactiveDismissDisabled(true)` to ensure explicit confirmation).

**Accessibility:** UIAccessibility.post announcement "Thank you for your support!" on appear.

### 4. SettingsView — New Sections

**Existing sections remain unchanged** (Daily Reminder, Win Reminder, streak display).

**New sections appended after existing Win Reminder section, in order:**

**"Appearance" section:**
- `Section("Appearance")` Form section
- `Picker("Appearance", selection: $colorSchemePref)` with `.pickerStyle(.segmented)`
- Options: "System" / "Light" / "Dark" (from `ColorSchemePreference.allCases`)
- Selected option is the active preference; change takes effect immediately (no restart, no confirm dialog)
- Stored in `@AppStorage("vg_colorScheme")` with stable raw values `"system"` / `"light"` / `"dark"`

**"Privacy" section:**
- `Section("Privacy")` Form section
- `Toggle("Public Profile", isOn: $isPublicBinding)` wired to existing `UserProfile.isPublic` SwiftData field via `ProfileViewModel.toggleProfilePublic(context:)` or direct binding
- When toggled ON: profile is visible to other users in community features
- When toggled OFF: profile is hidden from community features
- No confirmation required (toggle can be reversed immediately)

**"Support" section:**
- `Section("Support")` Form section
- Row 1: "Contact Support" — `Button` that calls `openURL(URL(string: "mailto:VitaminG.info@gmail.com?subject=Vitamin%20G%20Support")!)`. Uses `.foregroundStyle(VGTheme.accentTerra)` to indicate tappability. Guard with optional binding before calling `openURL`.
- Row 2: "About Vitamin G" — `NavigationLink(destination: AboutView())`. Standard Form row with chevron disclosure indicator.

**Section ordering in final SettingsView Form:**
1. Streak display (existing)
2. Daily Reminder (existing)
3. Footnote (existing)
4. Win Reminder (existing)
5. Footnote (existing)
6. **Appearance** (new)
7. **Privacy** (new)
8. **Support** (new — contains Contact + About rows)

### 5. NudgeTimePickerScreen (Conditional Onboarding Step)

**Entry point:** Conditional push from `NotificationOnboardingScreen.allow()` when permission is granted.
Step position: Step 7 of 8 (only when shown). `StepBarView(current: 6, total: 8)`.

**Layout:**
- Background: `VGTheme.sandLight.ignoresSafeArea()` (matches light onboarding screens)
- No NavigationBar (`.navigationBarHidden(true)`)
- `VStack(alignment: .leading, spacing: 0)`:
  - `StepBarView(current: 6, total: 8)` — top, 16pt top padding, 24pt horizontal padding
  - 32pt gap
  - Heading: `VGTheme.serif(34)` — "Pick your morning nudge time"
  - Subheading: `.system(size: 17)` muted — "When should we check in with you each day?"
  - 32pt gap
  - Chip row: `HStack(spacing: 8)` wrapping 5 chips — "6 AM", "7 AM", "8 AM", "9 AM", "10 AM"
    - Selected chip: `VGTheme.accentTerra` background, `VGTheme.warmWhite` text
    - Unselected chip: `VGTheme.surface` background, `VGTheme.textPrimary` text
    - Chip shape: `Capsule()`, 16pt horizontal / 10pt vertical padding, body 15pt font
    - Default pre-selected: "8 AM" (matches `NotificationPreferences.defaultHour == 8`)
  - 24pt gap
  - "Custom time" toggle row: `Toggle("Custom time", isOn: $showCustomPicker)` — when ON, reveals a `DatePicker` with `.datePickerStyle(.compact)` and `.datePickerStyle(.graphical)` alternative; when OFF, hides the picker and uses chip selection
  - Custom `DatePicker`: `.displayedComponents(.hourAndMinute)` only

**Save behavior:** Selecting a chip or changing the DatePicker updates `@State private var selectedHour` and `@State private var selectedMinute`. Calling `NotificationPreferences.save(hour:minute:)` and `NotificationScheduler.shared.reschedule(activeGoals:)` happen on the primary CTA tap (not on every chip tap).

**Footer (`.safeAreaInset(edge: .bottom)`):**
- Primary CTA: "Set my nudge time" — `.system(size: 17, weight: .semibold)`, full-width, `VGTheme.accentTerra` fill, warmWhite text, cornerRadius 14pt, 18pt vertical padding, 24pt horizontal padding
- Secondary link: "Skip for now" — `.system(size: 15, weight: .regular)`, `VGTheme.textMuted` color, full-width, 10pt vertical padding
- Both actions advance to `.cameraPermission` step
- "Set my nudge time" also calls `NotificationPreferences.save(hour:minute:)` and `reschedule(activeGoals:)`

**Dynamic step count:** When this screen is shown, `total: 8`. When it is skipped (permission denied), CameraPermissionScreen continues with its existing `total:` value — no retroactive change to earlier screens' step bars.

### Empty States

| Context | Heading | Body |
|---------|---------|------|
| TipJarView — products failed to load | (none — inline) | "Couldn't load tips. Check your connection and try again." |

### Error States

| Context | Copy |
|---------|------|
| TipJarView purchase error | Inline below tapped card: `store.purchaseError` (localized StoreKit error) or "Something went wrong. Please try again." |
| TipJarView pending purchase | "Purchase pending — check back soon." |
| Contact Support mailto fail | No fallback UI — `openURL` silently does nothing if no mail client; this is acceptable (standard iOS pattern) |

### Post-Purchase Confirmation

"Thank you!\nYou're the best."

Displayed as two lines centered on ThankYouView dark overlay. No feature announcement copy — tips are gratitude-only, no entitlement granted (MON-04).

### Rotating Notification Copy

Seven messages in `NotificationScheduler.inspirationalMessages` array (seeded by day-of-year). Required messages (from CONTEXT.md §Specifics):

1. "You got this! 💪"
2. "Take your daily Vitamin G 💊"
3. "Your goals are waiting ☀️"
4. "One step closer today 🌱"
5. "Make it happen 🔥"
6. "Progress, not perfection 🌿"
7. "Small steps, big results ⭐"

Notification body format when active goal exists: `"{message}\n{topGoalTitle}"`
Notification body format when no active goals: `"{message}"`
Notification title: `"Good morning"` — no emoji in title (avoid character rejection by iOS notification system).

### Destructive Actions

None in Phase 19. No delete, no account removal, no irreversible data actions. The profile privacy toggle is reversible. Confirmation dialogs are not required.
