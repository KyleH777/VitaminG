<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UserDefaults <-> SettingsView | `vg_colorScheme` raw string read by the picker; the @AppStorage enum binding tolerates unknown values |
| mailto: URL <-> system | A malformed mailto URL passed to `openURL` could fail; the string is app-controlled but still guarded |
| SwiftData UserProfile <-> Settings | The privacy toggle writes `isPublic`, which drives CloudKit public-DB visibility |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-04-01 | DoS | Malformed mailto URL crash | mitigate | The mailto string is passed through `if let url = URL(string:)` before `openURL` — no force-unwrap (19-RESEARCH.md Security Domain) |
| T-19-04-02 | Information disclosure | No PII in UserDefaults | mitigate | `vg_colorScheme` stores only an enum raw string ("system"/"light"/"dark") — no user data, no secrets in UserDefaults |
| T-19-04-03 | Tampering | Privacy toggle / isPublic write | mitigate | The toggle delegates to the existing `ProfileViewModel.toggleProfilePublic(context:)`, which already encapsulates the validated CloudKit public-DB write/delete path — Settings adds no new write logic |
| T-19-04-04 | Tampering | `vg_colorScheme` key consistency | accept | Stable lowercase raw values; @AppStorage falls back to `.system` on an unknown value; cosmetic-only impact |
| T-19-04-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager installs — native SwiftUI/SwiftData only; no slopcheck applicable |
</threat_model>
