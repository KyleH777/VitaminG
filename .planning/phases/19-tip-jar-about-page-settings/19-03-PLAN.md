<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| StoreKit servers <-> app | Purchase results carry an Apple-signed transaction; the signature gates delivery |
| App Store payment sheet <-> app | The user-facing purchase UI is owned by StoreKit; the app must not route payment outside it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-03-01 | Tampering | Unverified IAP transaction | mitigate | `TipStore.purchase` switches on `VerificationResult`; `.unverified` returns `(false, false)` and never sets `showThankYou` — an unverified/forged transaction yields no confirmation and no side effect |
| T-19-03-02 | Spoofing | Forged purchase / receipt | mitigate | StoreKit 2 verifies the JWS signature automatically; no hand-rolled receipt validation (19-RESEARCH.md "Don't Hand-Roll") |
| T-19-03-03 | Information disclosure | External payment link bypassing App Store | mitigate | TipJarView and TipThankYouView contain zero `http` URLs (grep-gated in verify); D-09 / MON-03 / App Store Guideline 3.1.1 |
| T-19-03-04 | Elevation of privilege | Feature unlocked by a tip | mitigate | MON-04: consumables grant no entitlement; TipThankYouView shows gratitude copy only, no feature announcement; `Transaction.updates` (Plan 02) only calls `finish()` |
| T-19-03-05 | DoS | Double-purchase from rapid taps | mitigate | The tapped tier's Buy button is disabled via `purchasingProductID` while a purchase is in-flight |
| T-19-03-06 | Tampering | Product ID mismatch (empty list) | mitigate | `TipProductID` raw values are byte-identical to VitaminGTips.storekit; an empty list surfaces as a visible error state, not a silent failure |
| T-19-03-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager installs — native StoreKit only; no slopcheck applicable |
</threat_model>
