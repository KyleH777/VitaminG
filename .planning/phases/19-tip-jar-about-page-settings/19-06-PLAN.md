<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UserDefaults <-> nudge-time save | The selected hour/minute is written to UserDefaults and the App Group; values feed UNCalendarNotificationTrigger |
| Custom DatePicker <-> scheduler | A custom time chosen by the user becomes notification trigger DateComponents |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-06-01 | Tampering | Out-of-range hour/minute in the scheduled trigger | mitigate | `NotificationScheduler.schedule` already clamps hour to 0-23 and minute to 0-59 (existing T-03-08); the nudge-time picker only offers 6-10 AM chips and a `.hourAndMinute` DatePicker, both within range |
| T-19-06-02 | Information disclosure | No PII written to UserDefaults | mitigate | Only an integer hour and minute are persisted via `NotificationPreferences.save` — no user identity, no secrets |
| T-19-06-03 | Spoofing | Conditional step shown without permission | mitigate | `.nudgeTimePicker` is appended only inside the `if granted` branch after `await requestAuthorization()`; a denied/skipped permission cannot reach the nudge-time step (D-13) |
| T-19-06-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager installs — native SwiftUI/UserNotifications only; no slopcheck applicable |
</threat_model>
