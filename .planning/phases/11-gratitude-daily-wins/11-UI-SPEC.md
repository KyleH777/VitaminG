## Spacing Scale

Native SwiftUI uses points (pt), not CSS pixels. All values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Inter-text spacing in VStack (e.g. title/description gap in GoalRowView: `spacing: 3` → round to 4) |
| sm | 8pt | HStack icon-to-label gaps, TierSectionView header spacing, small insets |
| md | 16pt | Default horizontal padding, section insets, card internal padding |
| lg | 24pt | Top padding in ScrollView VStack, card vertical padding on global streak card |
| xl | 32pt | EmptyStateView VStack spacing, horizontal padding on hero copy |
| 2xl | 48pt | Not used explicitly; reserved for major section breaks if needed |
| 3xl | 64pt | Not used in Phase 11 |

Exceptions:
- Touch targets: minimum 44pt × 44pt on all interactive elements (matches existing GoalRowView button frame)
- Card corner radius: 12pt (ProfileView card) and 14pt (TierStatCard) — follow 12pt for win history cards (matches ProfileView public goals card radius)
- TextEditor minimum height: 80pt (per RESEARCH.md §6 component breakdown)

## Typography

All font sizes are Dynamic Type semantic styles — no fixed `pt` sizes except in display-proportional numeral contexts (flagged below). Font design is `.rounded` on all user-facing labels. Maximum 4 declared levels.

| Role | SwiftUI Style | Weight | Line Height | Usage |
|------|--------------|--------|-------------|-------|
| Navigation title | `.largeTitle` (automatic via `.navigationBarTitleDisplayMode(.large)`) | Bold (automatic) | System default | "Daily Wins" navigation title — rendered automatically by nav bar, not declared inline |
| Section heading | `.title3.weight(.semibold)` | Semibold (600) | System default | Section labels: "Past Wins", today date header |
| Body / entry text | `.body` | Regular (400) | 1.5 (system default) | Win entry text in cards, TextEditor content; date labels and secondary info rows use `.body.foregroundStyle(.secondary)` — color differentiates, not a separate size level |
| Caption | `.caption` | Regular (400) | System default | Character count indicator ("0/500"), helper text, notification hint footer; compact metadata contexts use `.caption.foregroundStyle(.secondary)` — merged from former `.caption2` level |

Weight palette: exactly 2 declared weights — **Regular (400)** for body/caption and **Semibold (600)** for section headings and the Save button label (`.font(.headline)` which renders as semibold).

**Secondary differentiation rule:** Where a prior version declared `.subheadline` or `.caption2` as separate levels, use foreground style modifiers instead. Date labels and secondary info rows → `.body.foregroundStyle(.secondary)`. Compact metadata → `.caption.foregroundStyle(.secondary)`. This keeps the size palette at 4 levels while preserving visual hierarchy through color.

Display-proportional exception: none in Phase 11 (no large numeral displays — wins are text entries, not counters).

## Color

All semantic/adaptive colors use `Color(UIColor.systemGroupedBackground)` and `Color(.secondarySystemGroupedBackground)` — fully Light/Dark Mode adaptive per UI-05.

**Primary focal point:** TextEditor + Save Win CTA block at top of List. This is the first element the eye should reach. History list is secondary.

| Role | Light Mode Value | Usage | Source |
|------|-----------------|-------|--------|
| Dominant (60%) | `Color(UIColor.systemGroupedBackground)` — system off-white | ScrollView and List backgrounds | All existing views |
| Secondary (30%) | `Color(UIColor.secondarySystemGroupedBackground)` — elevated white/gray | Cards, form sections, win history cards | GoalListView, StatsView, ProfileView pattern |
| Accent (10%) | `Color(red: 0.98, green: 0.55, blue: 0.27)` — warm orange | Reserved-for list below | GoalTier.immediate, ProfileView share button, GoalRowView edit pencil |
| Accent gradient (paired with accent) | `Color(red: 0.78, green: 0.48, blue: 0.95)` — deep violet | Gradient endpoint only — paired with warm orange for hero/CTA elements | StatsView global streak card, EmptyStateView gradient |
| Completion green (semantic) | `Color(red: 0.063, green: 0.725, blue: 0.506)` | Completed goal states only — do NOT use in Phase 11 (wins are not completions) | GoalRowView |
| Destructive | `.red` (system semantic) | Swipe-to-delete action label background, confirmationDialog destructive button | GoalListView swipeActions pattern |

**Accent reserved for:**
1. The "Save Win" primary CTA button — warm orange gradient background (matching EmptyStateView CTA pattern)
2. The `book.pages` or `leaf` tab icon when the Wins tab is selected (tint follows tab bar accent)
3. The TextEditor cursor and selection tint (system-controlled via `.tint`)

Accent is NOT used on: card backgrounds, section headers, secondary text, the character count label, or history card backgrounds.

**Warm orange gradient** (accent + violet, `startPoint: .leading, endPoint: .trailing`): used only on the Save button background — mirrors EmptyStateView "Add Your First Goal" CTA gradient treatment exactly.

## Interaction Contracts

### Today's Entry Editor

- On view appear: check for today's entry (DailyWinsViewModel.todayEntry). If found, pre-fill `draftText`. If not found, show placeholder ("What's your win today?") via TextEditor's `.overlay` placeholder pattern.
- TextEditor is always visible at top — not behind a tap-to-expand disclosure. Inline edit (per CONTEXT.md Claude's Discretion: "either inline or sheet — inline is fine").
- Character count updates on every keystroke. At 500/500, further input is rejected at ViewModel layer (InputSanitizer).
- "Save Win" button is disabled when `draftText.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty`.
- On save: if today entry exists → update existing; if not → insert new. No animation on save beyond system List update.
- Keyboard dismissal: `.toolbar { ToolbarItem(placement: .keyboard) { Button("Done") { focusedField = nil } } }` — standard iOS keyboard toolbar pattern.

### History List

- Reverse-chronological sort: `@Query(sort: \DailyWin.date, order: .reverse)`.
- History shows all entries EXCEPT today's (filtered via `Calendar.current.isDateInToday`).
- Each row shows: date formatted as "Monday, May 1" (`Date.formatted(.dateTime.weekday(.wide).month(.abbreviated).day())`) and entry text (`.lineLimit(4)` in history — full text in a detail view if needed; Phase 11 shows truncated).
- Swipe-to-delete on history rows triggers `.confirmationDialog("Delete this win?", ...)` — mirrors GoalListView delete flow with "Delete" (destructive) + "Cancel" buttons and "This action cannot be undone." message.
- No bulk delete in Phase 11.
- Empty history state renders inline within the Section (no full-screen empty state — today's editor is always present above).

### Tab Icon

- SF Symbol: `book.pages` (per CONTEXT.md D-02 and RESEARCH.md §3 code snippet).
- Tab label: "Wins"
- Tab order: Goals (1) · Stats (2) · Wins (3) · Profile (4) — per CONTEXT.md D-01.
- Settings tab is removed from TabView; Settings is accessible via ProfileView as a NavigationLink row (RESEARCH.md §3 recommendation: Option A).

### Accessibility

- TextEditor has `.accessibilityLabel("Today's win entry")`.
- Save button has `.accessibilityLabel("Save win entry")` and `.accessibilityHint("Saves your win for today")` when enabled.
- History rows: `.accessibilityElement(children: .combine)` so date + text reads as a single VoiceOver element.
- Delete swipe action: `.accessibilityLabel("Delete win")`.
- Character count: `.accessibilityLabel("\(count) of 500 characters used")`.
- All animations gated on `@Environment(\.accessibilityReduceMotion)` — matches GoalRowView pattern.
- Dynamic Type: all fonts use semantic styles (.body, .caption, .headline) — no fixed sizes. TextEditor content inherits Dynamic Type automatically.
