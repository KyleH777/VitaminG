<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| iPhone → Watch WCSession channel | Apple-managed; payloads are dictionaries of property-list values; size limit ~64KB |
| JSONEncoder/Decoder for WatchSnapshot | Data round-trips through `[String: Any]` dictionary; must use Codable + Data to preserve types |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-02-01 | Tampering | WatchSnapshot JSON payload | accept | iOS app and Watch app are paired by Apple — channel is trusted; payload is non-sensitive (goal title, integer streak); no PII beyond what user already authored |
| T-27-02-02 | Information Disclosure | activeGoalTitle in dictionary | accept | Goal titles are user-authored; sharing with the user's own paired Watch is the intended behavior; not a leak |
| T-27-02-03 | Denial of Service | updateApplicationContext throw | mitigate | Wrap call in `do/catch`; log error via `#if DEBUG print`; do NOT crash app on WCSession unavailability |
| T-27-02-04 | Repudiation | Snapshot vs. truth divergence | mitigate | `updateApplicationContext` is last-writer-wins per RESEARCH.md Pitfall 3 — Wave 4 ensures snapshot push happens AFTER every check-in so Watch never sees stale state for more than one tick |
</threat_model>
