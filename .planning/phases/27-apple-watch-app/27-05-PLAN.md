## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Watch → iPhone transferUserInfo channel | Apple-managed paired-device channel; payloads queued and authenticated by signing |
| `userInfo["goalId"]` untrusted input | A malformed string could reach handleCheckIn if Watch payload is corrupt; validate via UUID(uuidString:) |
| WCSession delegate callback queue | Non-main background serial queue per Apple Documentation; touching SwiftData from this queue crashes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-05-01 | Spoofing | Foreign WCSession sender | accept | Apple's WCSession channel only delivers from the paired Watch's signed VitaminGWatch process — no cross-app spoofing possible |
| T-27-05-02 | Tampering | Invalid goalId in userInfo | mitigate | UUID(uuidString:) guard returns nil on malformed input; handleCheckIn returns early without invoking onCheckIn or side effects |
| T-27-05-03 | Information Disclosure | Goal lookup misses (goal id from older session) | mitigate | onCheckIn closure logs via #if DEBUG print and returns silently — no user-facing failure surface and no acknowledgement back to Watch |
| T-27-05-04 | Denial of Service | Background thread access to SwiftData | mitigate | session(_:didReceiveUserInfo:) dispatches to MainActor via DispatchQueue.main.async before any SwiftData touch (Pitfall 4) |
| T-27-05-05 | Elevation of Privilege | Replay of old userInfo payload | mitigate | addCheckIn's same-day dedup guard (line 170-174) makes repeated check-ins a no-op; Watch-side button is also disabled when hasCheckedInToday is true |
</threat_model>
