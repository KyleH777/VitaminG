<objective>
Stop discarding the Step 1 boolean answer in `ChallengeCheckInView`'s multi-step wizard. When the user taps Save on Step 2, the constructed `CheckInPayload.multiStep` must encode `multiStepBool` so the user's "Did you work out today?" answer is persisted on the resulting `CheckIn` record.

Purpose: Closes CR-02 from 13-REVIEW.md / 13-VERIFICATION.md gap 2. The Toggle on page 0 is bound to `@State multiStepBool`, but the current `save()` call constructs `CheckInPayload.multiStep(note: "", numericValue: ...)` — `multiStepBool` is never referenced, so the Step 1 answer is silently lost. This is a data-integrity bug that blocks CHAL-09 / SC-4.

Output: A single `save(payload:)` call inside `multiStepCheckInSection` that maps `multiStepBool` into the existing `note` parameter using the per-VERIFICATION.md guidance ("completed" / "skipped"). This is the minimal fix that uses the existing `CheckInPayload.multiStep` shape — no schema or ViewModel changes required.
</objective>
