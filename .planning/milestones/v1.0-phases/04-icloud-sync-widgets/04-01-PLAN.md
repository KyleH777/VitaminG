**ModelContainerFactory.swift changes (per D-07, WIDGET-03, Pitfall 2):**

Add a new static method `makeWidgetContainer()` below the existing `makeContainer()`:
```swift
/// Widget-safe ModelContainer: reads from App Group store but does NOT own CloudKit sync.
/// Widget process has no iCloud entitlement — using .automatic would crash on device.
/// Pitfall 2 from RESEARCH.md: widget must use cloudKitDatabase: .none.
static func makeWidgetContainer() throws -> ModelContainer {
    let schema = Schema(SchemaV1.models, version: SchemaV1.versionIdentifier)

    #if targetEnvironment(simulator)
    let config = ModelConfiguration(
        schema: schema,
        isStoredInMemoryOnly: false
    )
    #else
    let config = ModelConfiguration(
        schema: schema,
        isStoredInMemoryOnly: false,
        groupContainer: .identifier("group.com.kyleharrington.VitaminG"),
        cloudKitDatabase: .none
    )
    #endif

    return try ModelContainer(for: schema, configurations: config)
}
```

Key differences from `makeContainer()`:
- Uses `cloudKitDatabase: .none` instead of `.automatic` (widget process does not own sync)
- Never uses `inMemory` parameter (widget always needs persistent store)
- Same `groupContainer: .identifier(...)` so it reads the same App Group store as the main app

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App Group shared store | Widget process reads data written by main app process via shared SwiftData container |
| UserDefaults App Group suite | Widget reads notification time preferences written by main app |
| CloudKit sync | Main app syncs with iCloud; widget does NOT participate in sync (reads local store only) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | App Group UserDefaults | accept | Low risk: both reader (widget) and writer (app) are the same developer's signed code; App Group is sandboxed to the developer team |
| T-04-02 | Information Disclosure | Widget display of goal titles | accept | Goal titles are user-authored private data displayed on the user's own device; widget is read-only and does not transmit data |
| T-04-03 | Denial of Service | WidgetCenter.reloadAllTimelines() abuse | mitigate | System rate-limits reloads automatically; our code calls reload only on actual goal mutations (4 call sites), not on timer or loop |
| T-04-04 | Elevation of Privilege | Widget process writing to SwiftData | mitigate | StaticConfiguration used (no App Intents); no modelContext.insert or modelContext.delete in any widget target file; enforced by code review in Plan 02 |
| T-04-05 | Spoofing | CloudKit data injection | accept | CloudKit private database is scoped to the user's iCloud account; no public database exposure; Apple handles authentication |
| T-04-06 | Tampering | Widget ModelContainer using cloudKitDatabase: .automatic | mitigate | makeWidgetContainer() explicitly uses cloudKitDatabase: .none; widget process has no iCloud entitlement so .automatic would crash — the code prevents this |
</threat_model>
